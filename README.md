# 🔐 Password Manager

A full-stack **Password Manager** built using React, Node.js, Express.js, and MongoDB. This application allows users to store, view, copy, and delete website credentials through a simple and responsive user interface.

The project demonstrates full-stack web development concepts, including REST APIs, database operations, React state management, and frontend-backend communication.

## ✨ Features

* **Add Passwords:** Save website URLs, usernames, and passwords.
* **View Saved Passwords:** Display stored credentials in a table.
* **Copy to Clipboard:** Copy website URLs, usernames, and passwords with a single click.
* **Show/Hide Passwords:** Toggle password visibility for better usability.
* **Delete Passwords:** Remove saved credentials from the database.
* **MongoDB Integration:** Persist password records in a MongoDB database.
* **Responsive UI:** Access the application through a clean interface designed with Tailwind CSS.
* **Toast Notifications:** Receive feedback for actions such as saving or copying credentials.
* **Unique IDs:** Use UUIDs to identify password records.

## ⚙️ Prerequisites

Before running the project, make sure you have installed:

* [Node.js](https://nodejs.org/)
* npm (included with Node.js)
* [MongoDB Community Server](https://www.mongodb.com/try/download/community) or a [MongoDB Atlas](https://www.mongodb.com/products/platform/atlas-database) account
* [Git](https://git-scm.com/)

## 🚀 Installation and Setup

### 1. Clone the Repository

```bash
git clone https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
```

Navigate to the project directory:

```bash
cd YOUR_REPOSITORY
```

Replace `YOUR_USERNAME` and `YOUR_REPOSITORY` with your GitHub username and repository name.

### 2. Install Frontend Dependencies

From the project root, run:

```bash
npm install
```

### 3. Configure MongoDB

Set up a MongoDB database using either MongoDB Community Server or MongoDB Atlas.

Create a database and configure the connection details in your backend environment variables.

### 4. Configure Environment Variables

Create a `.env` file inside the `backend` directory:

```env
MONGO_URI=mongodb://127.0.0.1:27017
DB_NAME=passwordmanager
PORT=3000
```

**Important:**

* Change `MONGO_URI` if you are using MongoDB Atlas or another MongoDB connection.
* Ensure that the database server is running before starting the backend.
* Keep your `.env` file private. Never upload database credentials or secrets to GitHub.

### 5. Install Backend Dependencies

Open a terminal and navigate to the backend directory:

```bash
cd backend
npm install
```

If your backend dependencies are not already listed in `backend/package.json`, install the packages used by the server:

```bash
npm install express mongodb cors dotenv body-parser
```

### 6. Start the Backend Server

From the `backend` directory, run:

```bash
node server.js
```

The backend should start on the port configured in your `.env` file.

For example:

```text
Example app listening on port 3000
```

### 7. Start the Frontend

Open a **second terminal** in the project root directory and run:

```bash
npm run dev
```

Open the local URL displayed by Vite, usually:

```text
http://localhost:5173
```

Your Password Manager should now be running locally.

## 🔌 API Endpoints

The backend exposes the following REST API endpoints:

| Method | Endpoint | Description                             |
| ------ | -------- | --------------------------------------- |
| GET    | `/`      | Retrieve all saved password records     |
| POST   | `/`      | Add a new password record               |
| DELETE | `/`      | Delete a password record using its UUID |

### Example: Add a Password

**Request:** `POST /`

```json
{
  "id": "unique-uuid",
  "website": "https://example.com",
  "username": "user@example.com",
  "password": "example-password"
}
```

The `id` should be generated by the frontend using UUID and stored with the record.

### Example: Delete a Password

**Request:** `DELETE /`

```json
{
  "id": "unique-uuid"
}
```

The backend uses this UUID to identify and delete the corresponding record.

*Note: These examples assume your frontend field names and backend routes match this structure.*

## 🔒 Security Considerations

This project is intended for learning and demonstration purposes.

* Passwords should **not be stored as plain text** in a production application.
* Use appropriate encryption or a secure secrets-management design when storing credentials.
* Never expose MongoDB credentials, API secrets, or environment variables in a public repository.
* Add authentication and authorization before allowing users to access private password records.
* Use HTTPS in production.
* Validate and sanitize user input on the backend.
* Restrict database access and configure appropriate CORS policies.
* Avoid returning sensitive credentials to unauthorized users.

**Important:** This version should not be used to store real or sensitive passwords until suitable security measures have been implemented.
